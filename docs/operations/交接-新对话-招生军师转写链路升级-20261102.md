## 已完成能力

### 1. 爆款复刻改写方案

流程：

```text
确认原文
→ 拆解原文机制
→ 生成 3 套改写方案
→ 用户选择一套
→ 按同一方案生成 3 个版本
→ 选版进入定稿
```

强制约束：

- 三套方案必须正好 3 个且不重复。
- 方案必须包含 `sourceMechanism`、`targetBridge`、`thesis`、`beats`。
- 首轮结构不完整时自动修复一次。
- 三版共用同一个已选方案，只改变开场、语气、句式和节奏。

### 2. 视频转写来源

支持四种模式：

- `auto`：有有效口播用口播；没有口播再读画面文字。
- `speech`：只识别口播，不读画面文字。
- `visual`：只识别画面文字，不跑 ASR。
- `both`：两份都识别；都成功时为 `mixed` 合并稿。

`transcriptMode` 写入转写任务 payload，失败重试仍保留原模式。

### 3. ASR 幻觉防护

已过滤：

- `you`
- 英文片尾套话
- `字幕由Amara.org社区提供`
- 重复句
- 低置信无语音段
- 过短或纯套话结果

转写失败会清空旧文本，并显示真实的“没有识别到清晰口播”原因。

### 4. 画面文字回退

流程：

```text
ASR 为空
→ 场景变化检测
→ 8 个均匀基帧 + 最多 4 个场景变化帧
→ 最多 12 帧
→ 拆成两张 3×2 拼图
→ 多模态 TEXT 通道识别
→ transcriptSource=visual 或 mixed
→ 用户确认后才进入改写
```

当前返回元数据：

```json
{
  "frameCount": 12,
  "frameStrategy": "hybrid",
  "sheetCount": 2
}
```

真实视频对比：

| 方案 | 识别字符 |
|---|---:|
| 纯场景变化帧 | 35 |
| 单张 4×3、12 帧 | 165 |
| 混合抽帧 + 两张 3×2 | 215 |

### 5. 工作流内切换和恢复

确认原文页、失败页支持：

- 切换来源并重新提取。
- 新来源失败时恢复上一稿。
- 原视频不重新上传。

真实验收：

```text
visual / 274 字
→ 切换 speech
→ extract_failed
→ 恢复上一稿
→ visual / 原 274 字完整恢复
```

## 已知限制

1. 画面文字仍是“拼图后多模态识别”，不是逐帧 OCR；极快字幕仍可能漏字。
2. 当前只对画面文字回退做混合采样，仍未覆盖所有复杂版式和极小字号。
3. `both` 模式下口播和画面文字通过 `【口播】/【画面文字】` 标签合并，不是语义级自动对齐。
4. 客户端仍是未签名正式包。
5. 生产告警 Webhook 尚未配置。
