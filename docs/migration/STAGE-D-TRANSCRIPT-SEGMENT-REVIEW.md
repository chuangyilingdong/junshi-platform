# 转写分段校对与来源取舍 · 2026-11-03

## 目标

`both` 模式原来只把口播和画面文字用标签拼成一段 textarea，用户很难看出：

- 哪句话来自口播；
- 哪句话来自画面文字；
- 两段内容是否重复或冲突；
- 最终确认稿应该保留哪一部分。

本轮在原文确认页增加分段视图与快速取舍。

## 桌面端

新增“查看分段来源与时间码”折叠区：

- 每段显示来源：口播 / 画面；
- 显示时间码，画面文字显示抽帧生成的时间范围；
- 显示该段文本；
- 显示总段数、口播段数和画面文字段数。

快捷操作：

- 只保留口播：把确认稿替换为口播分段；
- 只保留画面文字：把确认稿替换为画面文字分段；
- 恢复合并稿：重新生成带【口播】/【画面文字】标签的合并稿。

用户手动编辑或执行来源取舍后，客户端保留当前草稿状态，轮询刷新不会把修改覆盖。

## 数据指标

确认原文时仍通过现有 `confirm_transcript` 动作提交最终文本，因此：

- 人工取舍会进入转写指标表的 `confirmation` 记录；
- `edit_ratio` 会把“只保留口播/画面文字”计入人工修改率；
- 不需要新增数据库字段或迁移。

## 验证

桌面 UX 回归：

```text
segmentCount=2
speechOnlyTranscript=切换后的口播片段。
visualOnlyTranscript=切换后的画面文字片段。
mergedTranscript=【口播】...+【画面文字】...
```

同时验证：

- 原转写模式切换仍正常；
- 恢复上一稿仍正常；
- 从分段取舍后确认原文仍能进入 3 套改写方案；
- 1100×720 无横向溢出。

## 边界

- 这是人工校对工具，不自动判断口播和画面文字哪一份“更对”。
- 时间码来自 ASR 分段或画面文字抽帧的近似位置，不是逐帧字幕对齐。
- 当前改动只在本地工作区，尚未提交或部署。
