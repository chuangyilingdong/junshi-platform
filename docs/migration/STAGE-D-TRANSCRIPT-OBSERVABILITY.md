# 转写质量与耗时监控 · 2026-11-03

## 目标

原来只能看到转写成功或失败，无法回答：

- ASR 和画面文字识别各耗时多久；
- 失败主要来自渠道、空结果还是抽帧；
- 人工确认时改动了多少；
- 哪种转写来源最稳定。

本轮新增独立指标表，不修改转写档案正文结构。

## 数据模型

迁移：

```text
deploy/migrations/49-junshi-workbench-transcript-metrics-mysql.sql
```

新表：

```text
junshi_workbench_transcript_metrics
```

每次 ASR/OCR 提取写一条 `event_type=extraction` 指标，包含：

- 模式、输入来源、最终来源、状态、总耗时；
- ASR 状态、耗时、字符数、分段数、语言、分片数、失败原因；
- 画面文字状态、耗时、字符数、抽帧数、拼图数、抽帧策略、失败原因；
- 最终字符数、分段数、视频时长。

用户确认原文时再写一条 `event_type=confirmation` 指标，包含：

- 原文和确认稿字符数；
- 归一化编辑比例；
- 是否因超长而截断计算。

长稿只对前 2000 字计算编辑距离，避免确认请求被阻塞。

## 聚合接口

```text
GET /api/junshi/workbench/metrics/transcripts?accountId=default&days=7
```

返回：

- 提取总数、成功数、失败数、成功率；
- 成功提取总耗时 `avg / p50 / p95`；
- ASR 成功、空结果、失败、平均耗时、平均字符数；
- 画面文字成功、空结果、失败、平均耗时、平均字符数、平均抽帧数；
- 人工确认次数、修改率、平均编辑比例、平均原文字符数；
- 主要失败原因；
- 按转写模式分布；
- 最近 20 条明细。

接口按机构和内容账号隔离，最多读取最近 5000 条指标。

## 桌面端

“任务中心”顶部新增“转写质量”面板：

- 近 7 天成功率；
- ASR 平均耗时；
- 画面文字平均耗时与平均抽帧数；
- 人工修改率；
- 总耗时 P50 / P95；
- 主要失败原因；
- 最近 5 条提取或人工确认记录。

## 边界

- 指标不回传作品正文、抖音 Cookie 或账号密钥。
- 当前只记录 Junshi 工作台内的转写提取和原文确认。
- 生产 MySQL 需先执行迁移 49，再部署对应 API。当前改动尚未提交或部署。
