# 创作链路合规体检 · 2026-11-03

## 目标

把已有的教培合规规则接入桌面创作链路，避免“生成时提示合规、发布时没人检查”的断点。

本轮覆盖四类可发布文本：

- 定稿标题、开场和完整口播；
- 口播成片、一键托管生成的口播稿；
- 编导稿里的口播、花字与字幕；
- 发布包标题、封面副标题、描述和话题标签。

## 服务端

新增受机构登录保护的工作台接口：

```text
POST /api/junshi/workbench/compliance/check
body: { "content": "待检查文本" }
```

接口复用 `complianceEngine.js` 的现有规则包，返回：

- `verdict`: `ok / fix / block`
- `hits`: 违禁词、绝对化用语等命中项及改法
- `redlines`: 资质红线
- `risky`: 长期预收、有奖销售、价格对比等经营风险提示
- `pass`: 是否无命中

旧 `/api/junshi/compliance` 与工作台接口共用 `auditMaterial()`，避免两套规则漂移。

## 客户端

新增“合规体检”面板，支持手动重新检查，并在以下动作前自动执行：

1. 保存内容方案；
2. 创建口播成片或一键托管；
3. 确认提交视频渲染；
4. 生成发布包。

拦截规则：

- `block`，或命中任一 `high` 级表述/资质红线：阻止保存方案、提交渲染和生成发布包；用户必须先修改文案。
- `fix`：允许继续，但显示命中词、风险提示和替换建议。
- `ok`：显示通过，不额外阻断。
- 体检接口不可用：给出明确错误；确认渲染和生成发布包时要求用户再次确认已人工核对。

用户修改任一文案字段后，旧体检结果立即失效，避免显示过期结论。
- 未保存的口播稿和分镜修改也会按当前页面内容体检，不会被已保存版本掩盖。
- 体检期间文案再次变化时会自动重查；仍不稳定则按高风险阻断，避免旧结果覆盖新文案。

## 验证

已通过：

```text
API: 46/46
Desktop: 5/5
Desktop UX: compliance.blocked=true, compliance.safe=true, talkingDraft=true, storyboardDraft=true
依赖审计: 30 个 API 文件，0 缺失
部署模板: passed
```

UX 回归覆盖：

- 普通招生文案返回 `ok`；
- API 返回 `fix` 但包含 `high` 级命中时，客户端仍按高风险拦截；
- “考试包过”触发资质红线和 `block`；
- 高风险文案无法保存内容方案；
- 修改为安全文案后重新体检恢复 `ok`；
- 1100×720 无横向溢出。

## 边界

- 这是规则词表 + 语境的快速初筛，不替代法律意见。
- AI 深度审读接口仍保留在旧 `/junshi` 页面，本轮没有把流式审读搬进桌面。
- 当前改动只在本地工作区，尚未部署生产。
